## 🔴 生产级阻断（5 个，不修不能上线）

### 1. 全局无 GC / TTL / 配额

**数据无限增长**：
- `history_archive` + `history_fts`：每次压缩前整段归档，永不删除
- `checkpoints`：每 3 轮存一份完整 history JSON，会话结束后不清理
- `summaries`：每次压缩 INSERT，无覆盖无清理
- `context_store/*.json`：每个卸载的工具结果一个文件，永久残留
- `lt_l1_atoms`：每 5 轮提取事实，永不删除永不合并
- Redis `session:{sid}:working_memory`：无 TTL，进程崩溃时 clear 不执行

### 2. SQLite 零并发保护

- 没有 `PRAGMA journal_mode=WAL`
- 没有 `PRAGMA busy_timeout`
- 每个调用点都 `new MemoryStore()` / `self._conn()` 新建连接
- FastAPI 并发请求直接 `database is locked`

### 3. 压缩与卸载互相破坏

- 压缩是 `history.clear() + history.append(summary)`
- 卸载的 `ref: ctx_xxx` 符号被当普通历史摘要掉
- 压缩后 ref_id 丢失 → 卸载的工具结果变孤儿 + agent 无法调取

### 4. 归档失败仍压缩 → 证据永久丢失

- `agent_context_compact` 里 archive 吞异常后照样 compact
- 原始 history 被破坏式清空且无归档备份

### 5. 调用方全 `except: pass` 静默吞错

- `agent_manager.py:197,212,246`、`agent.py:270,379,446,463`
- 磁盘满/SQLite 锁/schema 损坏时记忆系统静默失效

## 审计维度说明

每个组件按 7 个维度审计：
- A. 数据生命周期（TTL/GC/配额）
- B. 并发安全（锁/竞态）
- C. 持久化可靠性（原子性/事务）
- D. 错误处理（降级/告警）
- E. 性能（时间复杂度/N+1）
- F. 配置化（硬编码 vs 可配置）
